**Step 3: Add analyze namespace to Rakefile**

Insert a new `analyze` namespace after the `watch` task (at end of file, before any trailing whitespace). The analyze tasks must:
- Use `|| true` or equivalent to ensure non-zero exit from the tool does not fail the Rake task (advisory only per locked decision)
- Write output to `reports/` directory
- Create `reports/` if it does not exist

```ruby
namespace :analyze do
  desc "Run clang-tidy on all src/ files (advisory report)"
  task clang_tidy: "cmake:sanitize:configure" do
    mkdir_p "reports"
    sdk = `xcrun --show-sdk-path`.strip
    sh "/opt/homebrew/opt/llvm/bin/run-clang-tidy " \
       "-p build/sanitize " \
       "-source-filter '.*/tacticaltwo-game/src/.*' " \
       "-extra-arg=-isysroot#{sdk} " \
       "-quiet 2>&1 | tee reports/clang-tidy.txt; true"
    puts "\nclang-tidy report written to reports/clang-tidy.txt"
  end

  desc "Run cppcheck on src/ (advisory report)"
  task :cppcheck do
    mkdir_p "reports"
    sh "cppcheck " \
       "--project=compile_commands.json " \
       "--std=c23 " \
       "--enable=all " \
       "--suppress=missingIncludeSystem " \
       "--file-filter='*/src/*' " \
       "--output-file=reports/cppcheck.txt " \
       "--error-exitcode=0 2>&1 | tee -a reports/cppcheck.txt; true"
    puts "\ncppcheck report written to reports/cppcheck.txt"
  end

  desc "Run all static analysis (clang-tidy + cppcheck)"
  task all: [:clang_tidy, :cppcheck]
end
```

Key details:
- `clang_tidy` depends on `cmake:sanitize:configure` to ensure `compile_commands.json` exists and the sanitize build is configured
- Source filter uses `.*/tacticaltwo-game/src/.*` (NOT `.*\/src\/.*`) to exclude SDL3 `_deps/sdl3-src/src/` files
- `--extra-arg=-isysroot#{sdk}` resolves macOS SDK headers like `AvailabilityMacros.h` for Homebrew LLVM's clang-tidy
- `;true` after the pipe ensures Rake sees exit 0 even if clang-tidy has findings
- `--error-exitcode=0` tells cppcheck to always exit 0 regardless of findings
- `cppcheck` task does NOT depend on `cmake:sanitize:configure` because it uses the root `compile_commands.json` symlink directly (already retargeted by Plan 01)
- `analyze:all` task runs both in sequence for convenience

**Step 4: Run both analysis tasks to generate baseline reports**
